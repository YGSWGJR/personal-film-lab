## 4. 安装包体积对比与原因

| 指标 | 数值 |
|---|---|
| 旧包（打包前实测） | 291,428,347 B = **277.93 MiB** |
| 新包（本次构建） | 342,505,103 B = **326.64 MiB** |
| 差值 | **+51,076,756 B（+48.71 MiB，+17.5%）** |

**为什么变大了（非副本导致）**：

1. 旧 `release/` 是 **P1-D 之前的历史包**（H1-B 指令 §3 已注明）；新包首次完整包含 P1-D 的内嵌
   Python 运行时（解包后 176.7 MB，压缩后仍占主要增量）。
2. 旧包之后又合入了 S/W/T/D/P 批次的大量新代码与资源（设置/静帧/转码/检测/窗口遮挡、renderer 构建产物、
   设计素材等），`app.asar` 与资源随之增长。
3. 副本清理只回收 6.23 MB，无法抵消上述新增资源；因此体积上升属于**内容增长**而非打包污染，
   符合 H1-B 验收口径中「若体积反而上升，说明有新增资源，写进报告说明原因」。
