# 个人拉片工作台 · 开发架构文档

> 版本：v1.0（首版）
> 状态：作为 **dsh** 与 **codex** 的共同开发依据（权威文档）
> 上游依据：《个人拉片工作台产品方案V2》（`产品方案V2.pdf` / `拉片台产品方案V2_print.html`）
> 适用范围：桌面版个人工具，Electron + libmpv + FFmpeg + OpenCV + SQLite + yt-dlp

## 1. 文档说明与约定

### 1.1 用途与读者

本文档把《产品方案 V2》固化为可并行开发的工程约束，是仓库内 **唯一权威架构来源**。dsh 与 codex 在开发、联调、排错时以本文档与 `src/shared/` 下的类型/常量文件为准。

### 1.2 与产品方案的对齐关系

| 产品方案要点 | 本文档落点 |
|---|---|
| 不做教学分发，只做个人拉片工作台，核心交付物为「标准分镜本」 | 全部模块围绕「导入 → 切分 → 标注 → 截图 → 导出分镜本」主链路 |
| 三层时间轴：影片层/镜头层/标注层 | 渲染层 `Timeline` 组件；三层数据分别来自 player / shot / still+note |
| 镜头/场景检测（参考达芬奇 Scene Cut Detection） | `services/detect` 检测服务 + `DetectService` 调度 |
| 六大功能模块：导入/镜头分析/静帧截图/标注笔记/分镜本导出/学习统计 | 主进程 6 个业务服务 + 对应 IPC 域 |
| V1 MVP → V2 智能增强 | §9 开发顺序严格按 V1 → V2 分阶段落地 |
| 合规提示：在线解析仅支持自有或已获授权内容 | §5.6 ImportService 约束，UI 保留提示文案 |

### 1.3 全局规范（所有模块必须遵守）

- **时间单位**：所有时间戳统一为**毫秒整数**（`ms`），UI 展示时再格式化；检测服务内部可用帧号，产出时换算回毫秒。
- **坐标单位**：截图标注的框选/箭头/文字坐标统一用**归一化小数**（0~1，相对画面宽高），渲染与导出时再乘实际像素。
- **IPC 返回封装**：一律使用统一信封（见 §6.1）。
- **路径**：运行时数据一律落在 `app.getPath('userData')/lapian/` 下（见 §7.4），代码内不出现绝对路径硬编码。
- **语言/技术栈**：TypeScript 为唯一前端语言；主进程、预加载、渲染层共享 `src/shared/` 类型。
- **安全基线**：渲染进程 `contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`；渲染层不直接触碰 Node/文件/SQLite，一切经 preload 白名单 API。
- **变更流程**：任何影响模块边界、IPC 通道名、数据模型的改动，必须同步更新本文档与 `src/shared/`，再进入编码。

## 2. 技术栈

| 组件 | 选型 | 版本基线 | 职责 | 集成方式 |
|---|---|---|---|---|
| 桌面框架 | Electron | ≥ 33（稳定版，锁定后单独 PR 升级） | 主进程/预加载/渲染进程生命周期、窗口、系统能力 | npm 依赖 |
| 构建工具 | electron-vite + TypeScript | electron-vite 最新稳定 | 三端构建、热更新、打包 | 工程脚手架 |
| 渲染层框架 | Vue 3 + Pinia + TypeScript | Vue ≥ 3.4 | 三栏工作台 UI、状态管理（**渲染层内部选型，不影响模块边界，可整体替换**） | npm 依赖 |
| 播放内核 | libmpv（`libmpv-2.dll` dev 包，静态链接单文件，无需额外运行时库） | mpv ≥ 0.38 | 帧级播放控制：播放/暂停/seek/帧步进/取当前时间 | 主进程经 `koffi`（N-API FFI）直接调用 `client.h` API；画面经 `wid` 交由 mpv 的 vo/gpu（D3D11，render.h 同族渲染路径）画进 Electron 子窗口（见 §5.1）。DLL 位于 `resources/mpv/` |
| 视频处理 | FFmpeg / ffprobe（静态二进制） | 打包固定版本 | 抽帧、转码代理、缩略图、媒体探测、静帧导出取帧 | 主进程 `MediaService` spawn 子进程调用 |
| 色彩检测 | Python 3.11 + opencv-python + numpy + scipy | opencv-python ≥ 4.10 | 色彩特征提取、差异曲线、峰值检测、场景分组 | 独立检测服务进程，stdio JSON-RPC 2.0（见 §5.4） |
| 本地存储 | SQLite + better-sqlite3 | better-sqlite3 与 Electron ABI 匹配版本 | 项目/镜头/静帧/笔记/标签/术语库持久化 | 主进程数据层直连（同步 API + WAL） |
| 在线解析 | yt-dlp | 随发布打包最新版 | B 站/YouTube 链接解析与拉取 | 主进程 `ImportService` spawn 子进程，合规使用 |
| 数据校验 | zod | 最新稳定 | preload 边界与 IPC 载荷校验 | `src/shared/schemas.ts` |

**关键约束**：
- better-sqlite3 自 v13 起随 npm 包内置各平台 N-API 预编译（`prebuilds/win32-x64.node`），Electron 45（N-API 10）可直接加载，**无需 electron-rebuild**；打包时 `asarUnpack: node_modules/better-sqlite3/**` 且 `npmRebuild: false`，并用打包产物冒烟验证。
- FFmpeg、libmpv（`libmpv-2.dll`）、Python 检测服务运行所需二进制统一放 `resources/`，不依赖系统 PATH（开发期可回退系统 PATH 便于调试）。
- 渲染层不引入任何 Node 原生模块；三方依赖需确认在浏览器沙箱中可用。

### 3.1 进程拓扑

```
│            │                                                  │     │
│  ┌─────────▼──────────┐   ┌───────────────────────────────┐   │     │

```

### 3.2 通信拓扑规则

1. **渲染层 → 主进程**：仅通过 `window.api.*`（preload 里逐个声明的 IPC 封装），禁止直接 `ipcRenderer.send` 任意通道。
2. **主进程 → 渲染层**：仅通过 `webContents.send` 推送事件（`*.event:*` 通道），载荷同样走统一信封。
3. **主进程 ↔ 检测服务**：stdio 行协议 JSON-RPC 2.0，双向请求/通知，支持进度推送。
4. **主进程 ↔ libmpv / ffmpeg / yt-dlp**：libmpv 为进程内 FFI（koffi，`libmpv-2.dll`）；ffmpeg / yt-dlp 仍 spawn 子进程，走 stdout/stderr + 退出码。
5. **数据访问**：只有主进程内各服务可访问数据层；渲染层永不直接查 SQLite。

### 3.3 数据流（主链路）

```
导入(Import) → 建 Project → 探测(Media:probe) → 播放(Player)
   → 自动/手动切分(Detect/Shot) → 静帧截图(Capture) → 标注(Note/Tag)
   → 导出(Export:storyboard PDF/Word) → 统计(Stats)
```

## 5. 模块边界

> 每个模块：职责 / 依赖 / 对外接口（IPC 域）/ 明确不做的事。

### 5.1 PlayerService（播放，libmpv）

- **职责**：管理 libmpv 实例生命周期；封装播放/暂停/seek/帧步进/时间与帧号查询/音量；向渲染层推送播放状态事件。
- **集成方案（V1 采用，已落地）**：
  1. 主进程经 `koffi`（N-API FFI）加载 `resources/mpv/libmpv-2.dll`（**DLL 实际文件名是 `libmpv-2.dll`**，官方 dev 包命名；静态链接单文件，无需额外运行时库），直接调用 `client.h` 的 client API：`mpv_create` / `mpv_set_option_string` / `mpv_command_string` / `mpv_get_property` / `mpv_observe_property` / `mpv_wait_event`。
  2. 视频画面：主进程用 Win32 创建渲染子窗口（`STATIC` + `WS_EX_NOACTIVATE`，父窗口为 BrowserWindow 的 HWND），把 HWND 传给 mpv 的 `wid` 选项；mpv 的 vo/gpu 以 `gpu-api=d3d11` 经 render.h 同族的 GPU 渲染路径直接画进该子窗口。渲染层上报播放器区域的 CSS 矩形，主进程按 `scaleFactor` 换算物理像素同步子窗口位置与尺寸（窗口移动/缩放/DPI 变化均重算）。
  3. 原生子窗口会显示在网页内容之上，因此主进程启动时必须关闭 Chromium DirectComposition（`app.commandLine.appendSwitch('disable-direct-composition')`）；否则视频会被网页合成层盖住。
  4. 帧级控制：`frame-step` / `frame-back-step` + `seek <t> absolute+exact`；`hr-seek=yes`、`hr-seek-framedrop=no`。步进/seek 的落定判据：等待 `playback-restart` 事件 + `time-pos` 连续采样稳定 + `estimated-frame-number` 实际变化，避免「命令发出但画面未更新」。
  5. 事件：主进程每 10ms 轮询 `mpv_wait_event`，维护属性缓存；`player:event:time` 节流 ~100ms 推送。错误映射：文件不存在 / 文件为空 / 加载失败 / 格式不支持 / 解码失败 / D3D11 输出失败分别返回领域错误码，见 §6.2 与 `src/main/player/mpv-lib.ts`。
  6. 快捷键由渲染层捕获后经 IPC 调用主进程执行（Space 播放/暂停、←/→ 逐帧、Shift+←/→ ±1s），主进程不拦截键盘事件。
- **不采用**：spawn `mpv.exe` + JSON IPC（本 dev 包不含可执行文件；且进程内 FFI 才能拿到 `wid` 渲染与帧级状态）。
- **依赖**：`MediaService`（探测结果）、`resources/mpv/libmpv-2.dll`。
- **不做**：不解析视频文件、不落盘截图（截图归 CaptureService，通过 `still:capture` 传入目标时间，由 Capture/Media 取帧）。

### 5.2 MediaService（媒体处理，FFmpeg）

- **职责**（已落地于 `src/main/media/`）：
  - `probe`：ffprobe `-show_format -show_streams -of json`，解析时长/分辨率/帧率/容器/视频与音频编码/码率/文件大小/是否含音视频轨；
  - `extractFrame`：按时间点精确抽单帧（`-ss <t>` 前置 + `-frames:v 1`，accurate seek），支持 JPG/PNG 与质量参数，供静帧截图与分镜本缩略图；
  - `extractFrames`：按固定间隔批量抽帧（`fps=<1000/interval>` + 起止时间 + `maxFrames` 保护），供镜头检测采样；输出 `frame%06d.jpg`，返回每帧时间与路径；
  - `transcodeProxy`：生成低码率代理文件（libx264 + yuv420p + 最高 720p 不放大 + AAC 128k + faststart），**只写新文件、绝不修改源文件**；默认落到 `userData/lapian/proxies/`；
  - 统一 Promise 接口；每个任务带超时、失败诊断与错误码；长任务（抽帧/转码）通过 `media:event:progress` 上报进度，可用 `media:cancelJob` 取消。
- **实现要点**：
  - 子进程封装：`src/main/media/process-runner.ts` 统一 spawn、收集 stdout/stderr（stderr 保留尾部）、超时/取消时结束进程树；
  - 二进制解析：`src/main/media/ffmpeg-binaries.ts` 开发期取 `<repo>/resources/ffmpeg`，打包后取 `<resourcesPath>/ffmpeg`，兜底系统 PATH；启动时校验 `-version` 并缓存；
  - 失败诊断：`MediaError` 携带 `details`（command / exitCode / stderr 尾部 / elapsedMs / timeoutMs / path），经 IPC 信封透传给渲染层；
  - 抽帧默认输出：单帧 `userData/lapian/frames/`；批量由调用方指定 `outputDir`（检测服务用 `projects/<id>/frames/`），重跑时只清理同 prefix+扩展名的旧帧。
- **依赖**：`resources/ffmpeg`（FFmpeg 9.0.2 静态构建）；`ImportService`（源文件路径）。
- **不做**：不管理项目数据（归数据层）；不做任何画面分析（归检测服务）；不落库截图记录（归 CaptureService）。

### 5.3 ImportService（导入，本地 + yt-dlp）

- **职责**：
  - 本地导入：系统文件选择/拖拽（MP4/MKV/MOV 等）→ 校验 → 建 `Project` 记录 → 触发 `MediaService.probe` →（按设置）转码代理；
  - 链接导入：yt-dlp 解析 B 站/YouTube 链接 → 下载或仅解析（`--dump-json` / 下载到媒体库）→ 建项目。
- **合规约束**：仅支持自有或已获授权内容；界面保留合规提示文案；不实现任何绕过平台限制逻辑。
- **依赖**：`MediaService`、数据层、yt-dlp 二进制。
- **不做**：不参与切分/播放/导出。

### 5.4 DetectService（检测调度，OpenCV）

- **职责**：
  1. 准备：调用 `MediaService` 抽帧（帧序列落到 `projects/<id>/frames/`），携带参数（灵敏度、最小镜头时长、过渡过滤开关、权重）；
  2. 调度：spawn Python 检测服务（stdio JSON-RPC 2.0），逐条下发参数与帧目录，接收进度与结果；
  3. 结果：将剪辑点候选 + 场景分组换算为毫秒边界，产出「预览结果」；
  4. 应用：用户确认后写回 `shots`（origin=auto）与 `scenes`。
- **检测流水线（与产品方案一致）**：
  `① FFmpeg 抽帧采样 → ② 每帧特征（饱和度S/对比度C/亮度V/色调直方图H）→ ③ 帧间差异 ΔS+ΔC+ΔH 加权合成差异曲线 → ④ 自适应阈值+最小间隔峰值检测（剪辑点候选）→ ⑤ 色彩相近帧聚类成场景，映射镜头层，手动校准`
- **可调参数**（默认值见 §7.3 与 `params.py`）：`sensitivity`（阈值缩放）、`minShotSeconds`、`filterTransitions`（淡入淡出/闪白）、`weights{S,C,H}`。
- **接口**：IPC 域 `detect:*`；进度经 `detect:event:progress` 推送。
- **实现（已落地）**：`src/main/detect/detect-service.ts` 负责异步任务、FFmpeg 抽帧、Python stdio JSON-RPC、毫秒换算和 apply；`src/main/detect/python/` 实现 HSV 的 S/C/V/H 特征、加权差异曲线、自适应峰值、过渡过滤与场景聚类。预览镜头使用临时 `id` 定位，`detect:apply` 只写用户确认的候选。
- **写库规则**：apply 在事务内删除未锁定镜头、保留 `locked=1` 镜头并跳过与锁定区间重叠的候选；新镜头写为 `origin='auto'`，场景表整体替换为本次确认结果。
- **不做**：不直接读 SQLite；不接触 UI；不负责手动打点（手动归 `shot:*`）。

### 5.5 CaptureService（静帧截图）

- **职责**：按目标时间精确取帧（优先 `MediaService` 精确抽帧，保证确定性）；写 PNG 原图 + JPEG 缩略图；创建 `still` 记录并关联镜头；维护标注（框选/箭头/文字，归一化坐标）；快捷键 S 由渲染层捕获后调用 `still:capture`。
- **依赖**：`MediaService`、数据层。
- **实现（已落地）**：`src/main/capture/capture-service.ts` 统一执行“PNG 原图 → 480px JPEG 缩略图 → `stills` 记录”链路，失败时清理半成品文件；`still:captureAt` 取镜头区间中点并复用或创建 `role=auto-thumb` 记录；普通截图创建 `role=main` 记录。标注经 `still:setAnnotation` 以归一化坐标持久化。渲染层通过只读 `lapian-asset://` 协议加载项目内缩略图。
- **不做**：不操作 mpv 的截图命令（避免与播放状态耦合，保证截图确定性）。

### 5.6 ExportService（分镜本导出）

- **职责**：
  - 装配：按镜头顺序取 shot + 代表性静帧（缩略图列、画面内容列）+ 标注（景别/机位/运镜/光线/声音/备注）+ 台词/声音笔记，生成分镜本行数据；
  - 生成：PDF（固定排版，A4，模板化表头）与 Word（可编辑表格）；
  - 预览与范围：导出前预览（临时 PDF），支持勾选镜头范围、自定义表头。
- **分镜本列**（对齐产品方案）：镜号 / 时长 / 缩略图 / 景别 / 摄法·运镜 / 画面内容（静帧截图）/ 台词·声音 / 备注。
- **依赖**：数据层（装配）、`resources`（字体）、静帧文件。
- **实现（已落地）**：`src/main/export/export-service.ts` 从 S06 直接装配八个固定列；缺失缩略图时调用 `still:captureAt` 生成 `role=auto-thumb` 的 480px JPEG；画面内容优先取靠近镜头中点的 `role=main` PNG。PDF 使用 Electron `webContents.printToPDF` 生成 A4 竖版（含封面、重复表头、防止行跨页），Word 使用 `docx` 生成可编辑表格并显式指定 Microsoft YaHei 字体。成品写入 `projects/<projectId>/exports/`。
- **不做**：不渲染 UI（预览走临时文件 + 系统打开/内置预览页）。

### 5.7 StatsService（学习统计）

- **职责**：标签分布统计（镜头语言使用频率）、镜头时长节奏分析（全片节奏曲线数据）、个人拉片进度与复盘。
- **不做**：不做任何推断/推荐。

### 5.8 数据层（DataLayer）

- **职责**：SQLite 连接（WAL、外键开）、版本化迁移、按领域提供仓储（repositories）；所有写操作必须走 `db.transaction`。
- **实现（已落地于 `src/data/`）**：
  - `db.ts`：单库 `userData/lapian/lapian.db`（测试可用 `DSH_DATA_ROOT` 覆盖），`journal_mode=WAL`、`foreign_keys=ON`、`busy_timeout=5000`；`PRAGMA user_version` 版本化迁移，迁移失败整体回滚；
  - `migrations/001_init.sql`：`projects` / `shots` / `stills` / `tags` / `shot_tags` / `notes` / `terms` 七张表 + 索引；
  - `migrations/002_preset_tags.sql`：六类内置标签词表；`migrations/003_detect.sql`：`scenes` 表及 `shots.origin/locked` 字段（`settings` / `export_records` 后续迁移补）；
  - `repositories/`：`projects` / `scenes` / `shots` / `stills` / `tags` / `notes` / `terms` 七个仓储，全部写方法内部 `db.transaction(...)`；子实体写入时在同一事务内刷新 `projects.updated_at`；
  - `project-package.ts`：项目保存 / 另存为 / 打开（项目文件格式见 §7.4 末）；
  - 领域错误 `DataError`（`PROJECT_NOT_FOUND` / `SHOT_NOT_FOUND` / `INVALID_ARGUMENT` / `TAG_EXISTS` / `PACKAGE_INVALID` 等）经 IPC 信封透传。
- **V1 落地偏差（相对 §7.1 类型稿）**：
  - `shots` 表把镜头语言字段落成业务列：`shot_size`（景别）、`camera_method`（摄法）、`dialogue`（台词）、`remark`（备注）；`index` 已保留，`origin/locked` 由 migration 003 提供；
  - `tags` 与镜头通过 `shot_tags` 多对多关联（标签库全局，不按项目隔离）；`terms` 为全局术语库；
  - `stills.annotations_json` 存归一化坐标标注 JSON 字符串，读取时解析为数组。
- **不做**：不含业务规则（规则在各服务）。

### 5.9 渲染层（Renderer）

- **职责**：三栏工作台（镜头列表 / 播放器+三层时间轴 / 镜头详情卡）、快捷键（S 截静帧等）、标注表单、导出预览、统计视图；状态用 Pinia 管理。
- **不做**：任何文件/数据库/子进程操作。

## 6. IPC 通道清单（全部）

### 6.1 通道命名与封装规范

- 命名：`<域>:<动作>`；主进程→渲染层事件用 `<域>:event:<事件>`。
- 方向：**I** = invoke（渲染层发起，主进程 handle，返回 Promise）；**E** = event（主进程推送）。
- 统一信封：
  ```ts
  type IpcResult<T> = { ok: true; data: T } | { ok: false; error: { code: string; message: string; details?: Record<string, unknown> } };
  ```
- 通道名常量唯一来源：`src/shared/ipc-channels.ts`；preload 与主进程 `ipc/` 注册器都引用该文件，禁止手写字符串。
- 载荷校验：preload 侧用 `src/shared/schemas.ts`（zod）校验入参，非法载荷直接拒绝。

## 7. 数据模型

### 7.1 核心 JSON 结构

#### Project

```json
{
  "id": "1f9c2a3e-...",
  "name": "让子弹飞 拉片",
  "source": { "type": "local", "path": "D:/media/让子弹飞.mkv", "url": null, "platform": null },
  "media": {
    "filename": "让子弹飞.mkv", "container": "mkv",
    "durationMs": 7543200, "width": 1920, "height": 1080,
    "fps": 23.976, "videoCodec": "h264", "audioCodec": "aac",
    "sizeBytes": 1523456789, "proxyPath": null
  },
  "detectOptions": {
    "sensitivity": 0.62, "minShotSeconds": 0.5, "filterTransitions": true,
```

| 字段 | 类型 | 说明 |
|---|---|---|

| `timeMs` | number | 取帧时间点 |
| `filePath` / `thumbPath` | string | 相对 `userData/lapian/` 的相对路径 |
| `caption` | string | 一句话说明（分镜本备注/画面说明来源之一） |
| `role` | `'main' \| 'auto-thumb'` | 正式静帧 / 自动缩略图 |
| `annotations[]` | Annotation[] | 归一化坐标（0~1）；`box` 用 x/y/w/h，`arrow` 用 points，`text` 用 x/y + label |

#### Note

```json
{
  "id": "n-001",
  "projectId": "1f9c2a3e-...",
  "shotId": "7b0e2d1f-...",
  "text": "推镜+特写制造情绪压迫感，暗示主角察觉异常。",
  "createdAt": "2026-10-23T10:15:00.000Z",
  "updatedAt": "2026-10-23T10:15:00.000Z"
}
```

#### Tag

```json
{
  "id": "t1",
  "category": "景别",
  "name": "特写",
  "color": "#e11d48",
  "builtin": true,
  "sortOrder": 3,
  "createdAt": "2026-10-23T09:00:00.000Z"
}
```

| 字段 | 说明 |
|---|---|
| `category` | `'景别' \| '机位' \| '运镜' \| '光线' \| '声音' \| '剪辑' \| 'custom'`（预置六类 + 自定义） |
| `builtin` | 是否预置（预置不可删，可隐藏） |
| `sortOrder` | 同类别内排序 |

- **预置词表（migration v2）**：
  - 景别：远景 / 全景 / 中景 / 近景 / 特写
  - 机位：正面 / 侧面 / 过肩 / 俯拍 / 仰拍
  - 运镜：固定 / 推 / 拉 / 摇 / 跟 / 手持
  - 光线：自然光 / 冷光 / 逆光 / 硬光
  - 声音：对白 / 环境 / 音乐 / 无声
  - 剪辑：硬切 / 叠化 / 闪白

### 7.2 辅助模型（检测与术语库）

- **Scene**：`{ id, projectId, index, label, startMs, endMs, createdAt, updatedAt }` — 场景分组结果，映射到镜头层。
- **ShotPreview**：`{ id, index, startMs, endMs, durationMs }` — 检测预览的临时镜头；`id` 仅用于 `detect:apply` 选择确认，落库时生成正式镜头 id。
- **Term**（术语库条目）：`{ id, category, term, definition, builtin, sortOrder, createdAt }` — 供详情卡「一键插入标注」；JSON 导入导出使用 `{ category?, term, definition }[]`。
- **ExportRecord**：`{ id, projectId, format, filePath, shotRange, createdAt }` — 导出历史。
- **DetectJob**（内存态，不落库）：`{ jobId, projectId, status: 'running'|'done'|'cancelled'|'error', progress, result? }`。

### 7.3 DetectOptions（检测参数）

```json
{
  "sensitivity": 0.62,
  "minShotSeconds": 0.5,
  "filterTransitions": true,
  "weights": { "s": 0.3, "c": 0.3, "h": 0.4 },
  "frameInterval": 1
}
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `sensitivity` | 0.62 | 阈值缩放系数（越高越敏感/越多切点） |
| `minShotSeconds` | 0.5 | 最小镜头时长，低于此的候选被合并 |
| `filterTransitions` | true | 过滤淡入淡出/闪白等过渡 |
| `weights` | S0.3 / C0.3 / H0.4 | 差异曲线加权 |
| `frameInterval` | 1 | 抽帧间隔（帧），调大加速检测 |
| `intervalMs` | 自动 | 直接指定抽帧间隔毫秒（≥50），优先于 `frameInterval`；端到端快速验收可设 2000~5000 |

### 7.4 SQLite 存储约定

- 库文件：`userData/lapian/lapian.db`，WAL 模式，外键开启。
- 表：`projects` / `scenes` / `shots` / `stills` / `notes` / `tags` / `shot_tags` / `terms` / `settings` / `export_records`。已建：`projects` / `scenes` / `shots` / `stills` / `tags` / `shot_tags` / `notes` / `terms`（`settings` / `export_records` 后续迁移补）。
- 关键索引：`shots(project_id, start_ms)`、`stills(project_id, shot_id)`、`notes(project_id, shot_id)`、`shot_tags(tag_id)`。
- 文件目录约定（`userData/lapian/` 下）：

```
userData/lapian/
├── lapian.db
├── projects/<projectId>/
│   ├── source/        # 源视频（本地导入引用或复制；链接导入下载到此）
│   ├── proxy/         # 转码代理文件
│   ├── frames/        # 抽帧序列（检测用，可重建）
│   ├── stills/        # 静帧 PNG + thumb 目录
│   └── exports/       # 导出的 PDF/Word
```

- 迁移：`src/data/migrations/` 按版本号递增（`001_init.sql` …）；启动时 `PRAGMA user_version` 比对并执行未应用迁移。
- **项目包（项目保存 / 另存为 / 打开）**：单个 `.lapian`（zip）文件 =
  - `manifest.json`：`{ format: 'lapian-project', version: 1, projectId, name, exportedAt, includesAssets, includesMedia }`；
  - `project.db`：只含该项目数据的 SQLite 快照（与主库同 schema，可用任意 SQLite 工具打开排查）；
  - `assets/<stills|frames|exports>/…`：项目资源文件（默认打包；`source/` / `proxy/` 视频默认不打包，`includeMedia: true` 才包含）。
  打开时在事务内导入并重映射 id（项目/镜头/静帧/笔记/标签），id 冲突自动换新 id 并加「（导入）」后缀，资源复制进新项目目录。

## 8. 关键流程

### 8.1 导入 → 可播放

```
ImportService(本地/yt-dlp) → project:create → MediaService.probe → （可选）转码代理
→ player:open（PlayerService 加载源或代理）→ 渲染层播放器就绪
```

### 8.2 镜头分析（自动检测）

```
detect:run(projectId, options)
 → MediaService 抽帧到 projects/<id>/frames/
 → spawn services/detect（stdio JSON-RPC）
    features.py 逐帧特征 → difference.py 差异曲线 → peaks.py 峰值检测 → clustering.py 场景分组
 → 进度经 detect:event:progress 推送
 → detect:event:done 返回预览（shots/scenes，未落库）
 → 用户手动校准（shot:merge/split/update、边界微调）
 → detect:apply(shotIds, sceneIds) 确认 → 事务写库（origin=auto；locked 镜头保留并跳过重叠候选）
```

### 8.3 静帧 → 标注 → 分镜本导出

```
still:capture(timeMs) → MediaService 精确取帧 → 写 PNG/缩略图 → 落 still 记录 → 关联 shot
→ note:upsert / tag:assign / still:setAnnotation（详情卡编辑）
→ export:preview → 勾选范围/表头 → export:storyboard(pdf|docx)
   装配：shot.index/durationMs → 缩略图列(role=auto-thumb 或首张) → 景别/运镜/光线(tags)
        → 画面内容(role=main 静帧+标注) → 台词/声音(notes) → 备注(caption)
→ export:event:done → exports/<projectId>/…
```

### 9.1 联调规则

1. **契约先行**：任何两端联调前，先冻结 `shared/` 中的通道名与类型；渲染层可用 mock 先开发（`src/renderer/api` 提供内存 mock 开关）。
2. **纵向切片**：每个阶段结束即联调，不做「全部写完再联调」。
3. **事件收敛**：高频事件（`player:event:time`）节流；事件订阅在组件卸载时清理，避免泄漏。
4. **错误面**：所有 IPC handler 捕获异常并返回 `{ ok:false, error }`；渲染层统一 toast。
5. **数据一致性**：检测/导入等长任务期间，用户可取消；取消后不留半成品记录（事务或清理）。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| libmpv 内嵌受 Chromium DirectComposition 遮挡 | 视频不显示 | 主进程启动时关闭 DirectComposition（已验证）；若 D3D11 初始化失败返回 `VIDEO_OUTPUT_FAILED` 明确报错 |
| better-sqlite3 原生模块与 Electron ABI 不匹配 | 启动崩溃 | v13 N-API 预编译兼容 Electron 45；打包 `asarUnpack` + `npmRebuild:false`，打包产物冒烟覆盖数据库 CRUD |
| Python 检测服务打包分发复杂 | 用户环境不可用 | 内嵌 Python 运行时或打包独立可执行（PyInstaller）；开发期走系统 Python |
| 不同编码容器/异常文件的抽帧失败 | 检测/截图失败 | MediaService 统一错误码；异常文件提示转码代理后再分析 |
| 长视频抽帧 + 特征计算耗时长 | 体验差 | 抽帧可中断、进度可见、帧间隔可调；检测结果缓存（按参数指纹） |
| yt-dlp 平台接口变化 | 在线导入失效 | 版本随发布锁定；失败降级提示手动下载 |
| 渲染层误用 Node 能力 | 安全隐患 | sandbox + contextIsolation + 白名单 API + zod 校验（§1.3 安全基线） |
